Проект включает в себя два приложения - клиент и сервер. Оба настраиваются в файлах ini.
Для каждого приложения есть свой набор реквайрементс, который сейчас одинаковый, но может быть установлен на разных серверах.
Генерация сообщений с сервера рандомных команд выполняется периодически (раз в 10 секунд), клиент при этом пишет в консоль и в файл лога, что он делает по команде. Отрисовки нет.

Команды передаются между сервером и клиентом по протоколу TLV8 через обычный TCP-сокет: тип TLV-записи соответствует полю
`type` из файла `commands` (например `0x12` для `ON`), а длина данных - полю `length` (так `OFF` и `COLOR` различаются
одним и тем же типом `0x13`, но разной длиной полезной нагрузки). Отдельно от этого сокета каждое приложение поднимает
свой aiohttp-сервер (`config.ini` -> `[DEFAULT]`) - сейчас это просто пустой HTTP-сервер без маршрутов, зарезервированный
на будущее (например, под health-check).

## Запуск

```
pip install -r requirements.txt
python LanternServer.py   # в папке "Сервер"
python LanternClient.py   # в папке "Клиент"
```

## Тесты

```
pip install -r requirements-dev.txt
python -m pytest tests/
```

Тесты покрывают кодирование/декодирование команд по TLV8, чтение конфигурации и настройку логирования.

## Обработка ошибок

Клиент и сервер переподключаются друг к другу при обрыве соединения (с паузой 5 секунд между попытками) и не падают
при временной недоступности другой стороны.

## Логирование

Логи пишутся одновременно в консоль и во вращаемый файл (`server.log` / `client.log` в папке приложения, до 1 МБ,
3 бэкапа) в кодировке UTF-8 - логика настройки вынесена в отдельный класс `AppLogger` (`logger.py`).
